## 先看见什么

一束暖白色光在暗处缓慢游移，周围散出细长星芒。视线顺着它与画面中心的连线移动，会遇到一串大小不同的光斑：有的宽而柔，有的边界更清楚，边缘微微分出颜色。它们是镜头鬼影的艺术化近似，不是真实镜片的光路模拟。

这个案例没有场景网格、距离场或光线步进。和熔彩流动的实体表面、星巢的体积积累不同，所有亮度都直接由二维坐标计算。读者只需掌握“离某个中心多远”，就能开始拆开画面。

## 一步一步拆开

### 1. 把像素变成以画面中心为原点的坐标

`uv()` 覆盖 `[0, 1]`，减去 `0.5` 后，中心成为原点。横坐标乘宽高比，使两个方向的距离单位相同，圆形光晕才不会被拉成长椭圆。

```ts
const aspect = resolution.x.div(resolution.y);
const p = screen.sub(0.5).mul(vec2(aspect, 1)).toVar();
const t = elapsed.mul(speed).add(0.7);
```

这里的 `resolution` 是实际绘制缓冲区尺寸。时间从原作第 0.7 秒开始，两个频率略有不同的正弦控制光源位置。竖屏缩小光源的水平运动幅度，让它留在较窄的画幅里；横屏保持原作比例。

桌面按下并拖动会为自动轨迹添加位置偏移，松开后保留偏移，悬停不改变画面。这与原作“按住时直接跟随鼠标、松开回到自动轨迹”不同；恢复默认值会清除偏移。移动端使用参数探索，横向滑动仍用于切换案例。

### 2. 用径向衰减画出主光源

先求当前像素到光源的距离。距离越大，亮度越低；分母加一，避免中心除以零。

```ts
const main = p.sub(light).toVar();
const core = float(1).div(length(main).mul(16).add(1));
```

单独看这一项，会得到平滑的圆形光晕。系数 `16` 决定衰减的快慢：越大，能量越集中。它不是物理意义上的平方反比定律，而是作者为画面选择的亮度曲线。

星芒来自方向差异：`atan(main.x, main.y)` 求角度，三角函数把角度变成噪声采样位置，再用噪声调制主光源。这里特意保留原作交换参数的角度方向；在光源中心为零向量时增加极小保护，避免两后端对 `atan(0, 0)` 的差异。

### 3. 沿光轴排列不同形状的鬼影

`p + light * k` 的零点位于 `-light * k`。因此正的 `k` 将光斑放在光源的另一侧，负值放在同侧。只调整系数，就能沿同一条轴排出多层鬼影。

```ts
const warped = p.mul(length(p)).toVar();
const wide = mix(p, warped, -0.5).toVar();
const tight = mix(p, warped, -0.4).toVar();
```

`warped` 用离中心的距离重新缩放坐标。`mix` 的权重为负时是外推，并不局限于两个输入之间；这一变形让光斑的空间分布更有镜头感。

柔和的一组用 `1 / (1 + 32 * distance²)`，另外几组用 `max(0.01 - distance^power, 0)`。幂次与增益共同决定光斑的范围、形状和强度。它们没有逐个画成几何圆盘，仍是同一个片元程序里的数值相加。

### 4. 让三个颜色通道稍微错位

同一组鬼影分别计算红、绿、蓝三个通道。每个通道的中心沿光轴稍微移动，便出现色散边缘。

```ts
const shift = float(index).mul(dispersion);
const offset = float(0.8).add(shift.mul(0.05));
```

`index` 是 0、1、2；它在 JavaScript 构建阶段展开为三个固定表达式，不是每帧在 CPU 上计算每个像素。把“色散距离”设为零，可以让同组 RGB 中心重合；通道增益仍然不同，所以不会自动变成灰色。提高“鬼影强度”再调色散，更容易观察彩色边缘。

源码用局部 `ghostChannel` 函数组织四组光斑，不需要额外渲染通道。未参与原作输出的 `n`、`f1` 计算没有进入 TSL，原始 GLSL 则完整保留供对照。

### 5. 用固定噪声和颜色调整收尾

原作通过 `iChannel0` 读取噪声图。本改编按获批范围，在 JavaScript 初始化阶段用固定种子的 xorshift32 填充 256 × 256 RGBA 字节，再创建 `DataTexture`。噪声不从网络获取，不在每帧重新生成。

```ts
const angularNoise = texture(noise, vec2(noiseCoordinate, 0).div(256)).r;
const grain = texture(noise, screen.mul(resolution).div(256)).r.mul(0.015);
```

第一个采样调制星芒，第二个为画面添加极轻的颗粒。纹理按数值数据读取，使用重复寻址、线性与 mipmap 过滤。固定种子让暂停、参数恢复与两后端比较可重复；它不是密码学随机数。由于没有沿用原噪声图，星芒细节和颗粒与原作不同，不能把这里的海报当作当前 Shadertoy 截图。

各光斑叠加后，乘暖色偏置，再根据 RGB 总和调整颜色。最后加上可调亮度、限制显示范围，将原作显示 RGB 解码为线性值，再由站点输出 sRGB，避免重复转换把画面洗白。光源中心保留原作有意的白色高光；高亮度参数会扩大这个区域。

## 可以亲手试什么

- **运动速度**：设为零，再拖动光源观察鬼影如何沿轴线移动。
- **整体亮度**：降到 0.3，观察强光周围的细节与暗部层次。
- **鬼影强度**：从零提高，分辨主光源与附加光斑的贡献。
- **色散距离**：提高鬼影强度后，从零逐渐拉开 RGB 中心。
- **星芒起伏**：设为零看均匀光晕，再恢复有方向差异的星芒。

暂停后参数和桌面拖动仍有效。恢复默认值会同时重置时间、位置偏移和五个参数。

## 性能观察

这是一遍全屏片元绘制，每像素含两次噪声采样、四组 RGB 鬼影及若干 `pow`、`sin` 和 `atan`。没有 ray marching 循环，也没有外部素材加载；256 KiB 基础噪声加 mip 层约占 341 KiB。主要开销随绘制像素数增长，不能仅凭“单通道”就保证所有手机都流畅。

2026-09-13 在 Ryzen 9 7950X3D / RTX 4080 SUPER、Chromium 153.0.8010.37 的生产页面预热 3 秒后采样 120 个 RAF 间隔：桌面与移动模拟的两后端平均均为 6.06 ms，p95 为 6.1–6.2 ms。持续 45 ms/帧主线程负载下 DPR 从 1 降至 0.8。

运行时沿用自适应 DPR、隐藏页暂停，以及 `prefers-reduced-motion` 下先显示海报的行为。本机测量、WebGPU/WebGL2 检查和真实后台事件的验证边界见同目录 VALIDATION.md；帧调度间隔不是 GPU 执行时间，桌面移动视口模拟也不是实体手机性能。
