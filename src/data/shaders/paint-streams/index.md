## 先看见什么

橙色和蓝色颜料从上方流入，在中央相遇，落到容器底部后形成薄片、细滴与混色。它的形状需要上一帧留下的状态；只知道当前时间，无法直接写出每一滴的位置。

「青弧粒场」每帧按公式重新放置光点，「熔彩流动」寻找三维距离场的表面。这次学习怎样把**位置、速度、质量和颜料成分留在二维网格**，反复读入、更新，再画成可以辨认的液流。

默认画面先推进 600 个固定步，也就是 60 步/秒下的前十秒，再继续播放。改变重力、压力或分布宽度会重演这段过程，方便比较同一起点下的结果。模拟速度只影响后续推进次数；暂停时调节它不会移动液流。默认状态保存为 GPU 检查点，重置或恢复默认物理参数时直接还原。

## 一步一步拆开

### 1. 一个网格单元保存一个平均状态

把每个像素格子看成一个小容器。它保存质心相对格子中心的偏移、速度、质量，以及颜料成分。这里的“粒子”是格子里物质的平均描述，并非一个可以自由增加数量的独立点列表。

原作把两个 16 位数打包到一个浮点通道。某些位型会成为 NaN，跨渲染后端保存时存在差异。移植使用两个 RGBA32F 附件分别保存运动状态与质量数据，保留原作的 16 位量化公式：

```ts
const quantized = round(clamp(value.mul(0.5).add(0.5), 0, 1).mul(65534))
  .div(65534)
  .mul(2)
  .sub(1);
```

原始 JSON 与五段 GLSL 按字节保存；运行时不使用特殊浮点位型作为容器。这增加了状态纹理的内存用量，也使数据流更容易阅读。

### 2. 计算邻居将多少质量送进当前格子

Buffer A 先让邻居质心沿速度移动：`moved = center + velocity * 1.5`。接着将每个质心展开成一个小矩形，计算它与当前格子的重叠面积。重叠比例决定这个邻居存入当前格子的质量。

```ts
const low = clamp(moved.sub(diameter.mul(0.5)), point.sub(0.5), point.add(0.5));
const high = clamp(moved.add(diameter.mul(0.5)), point.sub(0.5), point.add(0.5));
const overlap = high.sub(low);
const deposited = neighborMass.mul(overlap.x).mul(overlap.y).div(diameter.mul(diameter));
```

遍历周围 5×5 个格子，累计质量，并以质量加权位置、速度和颜料成分，最后除以总质量。这就是原作者称作 **reintegration tracking** 的重积分过程：物质可以分给多个格子，多个来源也可以在同一格子合并。

分布较窄时，更容易留下细滴；较宽时，信息在格子之间交换得更多，画面也更平滑。它不是传统的纹理坐标反向采样。本文也不承诺整幅画面的总质量恒定：两个注入口持续增加物质，排出口会移走物质，边界与数值误差还会影响结果。

### 3. 用局部压力和重力更新速度

Buffer B 读取刚完成重积分的状态，比较邻居质心与当前质心的位置。原作用密度偏离静止密度的程度估算压力，再用高斯权重形成局部作用力：

```ts
const pressure = density.mul(density.div(0.5).sub(1)).mul(0.04);
const weight = exp(dot(delta, delta).negate());
force.subAssign(delta.mul(weight).mul(averagePressure).mul(0.5));
velocity.addAssign(force.mul(1.5).div(max(mass, 1e-12)));
```

重力向下拉动液流，边界法线抑制穿墙速度，最后把速度长度限制到 1，保证局部搜索不会漏掉跨得太远的物质。两个上方注入口分别写入蓝色和橙色成分，并轻微摆动方向。原作未启用的随机初始化、零系数黏性和零系数边界力没有加入计算；保留源码中的辅助哈希及其 MIT 署名。

这些局部压力表达式借用了 SPH 的思路，但数据结构仍是网格中的平均分布，不能把它当成经过物理精度验证的完整 SPH 求解器。

### 4. 将密度变化画成液体表面

Buffer C 根据邻居质心的高斯贡献生成密度场。这里保留一个容易漏读的原作细节：权重来自邻居位置，被乘的是**当前格子**的速度、质量和颜料成分，不能擅自改成邻居的数据。

最终 Image 在密度场左右、上下各取一个样本，形成梯度。梯度方向决定高光朝向，密度控制颜料覆盖程度；蓝橙混合在平方后的颜色之间插值，再开平方，形成原作偏明亮的混色。

白色背景是原作的视觉设计。最终用 `tanh` 压缩亮度，并在交给共享渲染器之前做 sRGB 解码，避免重复编码。原作边界的逆序 `smoothstep` 改写为 `1 - smoothstep(2.5, 10, distance)`；零法线与极小分母加入有限保护，纹理越界读取明确返回零。

### 5. 每一步都先更新状态，再显示

离屏过程保持 A → B → C 的依赖：A 读取上一轮 B，B 读取当前 A，C 读取当前 A；Image 最后显示密度。A 与 B 已形成反馈，所以每一步不能直接读写同一张状态纹理。

实时推进以 1/60 秒为调度单位，每次仍使用原作的模拟步长 1.5。刷新率较高时，一些显示帧只重画画面；较低时，一次显示可以推进多个模拟步，单次最多 12 步。暂停、重复绘制与仅调节高光都不会推进模拟。

模拟网格最长边为 400，与显示 DPR 分开。宽高比变化会重新建立状态并重演初始过程；单纯调整画质尽量保留同一个网格。移植未接入原作的鼠标搅动分支，交互重点是五个教学参数。

检查点保存持久状态 B 和显示密度 C；A 是下一步会覆盖的临时结果。还原时复制纹理，同时恢复模拟步数、调度余量和来源时间，所以播放也能从相同位置继续。这样默认重置不依赖再次求解后的数值轨迹。

## 可以亲手试什么

- **模拟速度**：比较单位播放时间里推进的固定步数；设为零后，液流保持当前位置。
- **重力强度**：观察相遇位置、下落速度和底部飞溅一起改变。
- **压力响应**：观察密集区域怎样影响流束形状；这会重演初始过程。
- **分布宽度**：比较细小液滴与更平滑的流动，理解数值扩散带来的取舍。
- **表面高光**：只改变密度梯度的照明，让模拟状态与显示方式分开比较。

## 性能观察与验证

每个模拟步包含两次状态绘制，每次搜索 5×5 邻域；显示前另有一次 3×3 密度绘制。固定网格限制了模拟开销，显示分辨率和 DPR 仍影响最终画面的成本。初始化和非默认物理参数变化会重演 600 步；默认重置只复制检查点的三个附件。

两个状态目标各有两个 RGBA32F 附件，另有一个密度目标，运行数据约 80 字节/格；检查点再占 48 字节/格。合计 400×250 时约 12.8 MB，最大 400×400 时约 20.48 MB，未计驱动与渲染器额外开销。它比原作更占内存，换取有限浮点状态在两个后端之间的明确表达和精确的默认恢复。

本机 Ryzen 9 7950X3D / RTX 4080 SUPER、Chromium 151 中，桌面 1440×900 与移动模拟 412×915 的 WebGPU / WebGL2 四组，在预热三秒后各取 120 个 RAF 间隔：平均约 6.06 ms，P95 约 6.1–6.2 ms。实际 WebGPU 为 NVIDIA/lovelace、fallback=false。RAF 间隔表示浏览器调度，不是 GPU 时间；移动模拟也不代表实机手机。

受控每帧 45 ms 的主线程负载使自动 DPR 从 1 降到 0.8；移动自动 DPR 达到 1.5。减少动态偏好下先显示海报，手动播放再启动后端。受控隐藏事件的 800 ms 观察期中，提交计数保持 2430，恢复后增至 2651；原生后台标签页暂停本轮没有可验证的新能力，不能用受控事件替代原生证据。

相同网格与 600 步下，原始 GLSL 与 TSL WebGL2 的内部区域平均 RGB 字节差约 0.200，最大 140；TSL 两个后端平均约 0.209，最大 158。液流的整体路径一致，细滴与薄片存在局部差异，不宣称逐像素相同。完整测试、媒体和数值记录见同目录 `VALIDATION.md` 与证据 JSON。
