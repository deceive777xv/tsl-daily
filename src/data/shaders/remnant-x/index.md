## 先看见什么

相机在银灰与暗红的结构之间缓缓穿行。圆孔、小格和弯曲的墙面向深处重复，近处像金属，远处融入深蓝。一束光随相机移动，有时从孔洞边缘闪出；极细的蓝色辉光又把贴近视线的结构勾出来。

这些细节没有对应的网格模型。和「孔隙方城」反复从方块中挖去十字孔不同，Remnant X 反复折叠**被查询的坐标**，用折叠后的长度估计离表面还有多远。它也不同于「星巢」的体积累积：先找到一个实体表面，再计算法线、着色和遮挡。

这是 David Hoskins 的原作静音视觉改编。原作的 Image、Sound 两份源码完整保留，本站不播放声音。来源未核验的原始噪声图片没有下载，换成了本站生成的确定性噪声；后面的天空与起步抖动因此不承诺逐像素相同。

## 一步一步拆开

### 1. 一次查询，要在坐标里走九轮折叠

先把空间中的一个点放进 `vec4(point, 1)`。前三个分量是位置，第四个分量用来记录累计尺度，和透明度无关。每轮先做盒折叠：

```ts
folded.xyz.assign(clamp(folded.xyz, -1, 1).mul(2).sub(folded.xyz));
```

在区间 `[-1, 1]` 内，坐标保持原样；超过边界后，它向边界另一侧折回。三个轴一起这样处理，就像把越过盒壁的查询点映回内部。

接着用点到原点的平方距离决定缩放倍率，这一步叫球折叠。靠近球心的区域受到更强的放大，再乘固定尺度并加回最初的查询点：

```ts
const radius2 = dot(folded.xyz, folded.xyz).toVar();
folded.mulAssign(clamp(max(float(0.25).div(max(radius2, 1e-12)), 0.25), 0, 1));
folded.assign(folded.mul(vec4(2.8).div(0.25)).add(initial));
```

九轮之后，用折叠后的长度除以累计尺度，得到距离估计。这里不是严格的解析 SDF，也没有真的建立无限层几何。`toVar()` 保存当前半径，避免位置更新后，节点表达式改用新的坐标重新计算。分母的极小保护只处理球心退化情形。

### 2. 大步靠近，最后用二分把位置收紧

每个像素发出一条射线。距离估计大的时候走得远，贴近表面后走得短；本例最多查询 100 次，超过 12 个世界单位就放弃搜索。起步加入很小的确定性噪声，打散整齐的采样条纹。

当估计值低于 `0.0005`，原作没有直接使用这个位置，而是保留上一个距离与当前距离，连续取六次中点：

```ts
midpoint.assign(dot(bracket, vec2(0.5)));
const distance = field(origin.add(direction.mul(midpoint)));
bracket.assign(mix(vec2(bracket.x, midpoint), vec2(midpoint, bracket.y), step(0.0005, distance)));
```

中点还在阈值之外，就把区间前端推到中点；已经进入阈值，就把后端拉回来。六轮会把初始区间缩小到约六十四分之一。它细化的是**距离估计阈值的命中区间**，并不保证找到了数学上精确的零点。对于满是小孔和薄边的结构，这一步能减少直接停在粗糙位置上的误差。

### 3. 让同一条迭代轨道决定颜色

几何找到以后，再从命中点出发做六轮相同折叠。这次不为搜索表面，而是记下每轮离原点最近的平方距离：

```ts
trap.assign(min(trap, radius2));
```

这就是本例的轨道陷阱：一个点在迭代过程中走过的路径，成为它的颜色线索。最小半径和最终长度共同决定红色、银灰与金色的混合，结构与颜色因此自然对应。沿距离传播的窄脉冲又会短暂把红色基底推向青蓝。

把「轨道着色」降到零，可以先看红色基底，再逐渐恢复银灰与金色的分区。它改变颜色权重，不会改变孔洞的位置。

### 4. 用两盏灯和法线，建立金属般的层次

在命中点周围沿三个轴各查两次距离估计，差分得到法线。然后分别朝固定方向光与随相机移动的光源走八步，估计光线受到的遮挡。小孔内部变暗，边缘与高光就更容易辨认。

「阴影强度」降到零时，比较的是保留表面朝向明暗、但去掉遮挡的结果。这里的亮斑来自反射方向与光源方向的幂函数，并没有继续追踪镜面反射射线，也不是完整 PBR 金属材质。

射线靠近表面时，还会积累一个额外量：

```ts
glow.addAssign(clamp(float(0.05).sub(distance), 0, 0.4));
```

「近面辉光」把这份累积染成蓝色，帮助观察细小轮廓。这是艺术化距离累积；远处的蓝雾也是按距离混色，不是物理体积散射。

### 5. 让相机沿曲线飞，而不是让几何旋转

三个不同频率的正弦、余弦决定相机位置，曲线上稍后的点决定朝向。滚转与额外视线旋转让廊道从画面不同方向掠过。源时间会先乘 `0.01` 再加 15，本站默认从原作第 2 秒开始。

「飞行速度」同时影响相机和光脉冲；「路径偏移」代替原作鼠标横向的时间偏移，可以快速比较不同路段。几何本身没有随这些参数移动。短循环使用一段实际浏览器渲染的前进与倒放画面来闭合，不代表原作相机轨迹本身严格周期相接。

## 阅读 TSL 时留意什么

`Fn`、`Loop` 和 `If` 描述的是 GPU 程序。JavaScript 在这里搭建节点图，九轮几何查询和逐像素步进发生在 GPU 中。带 `setLayout` 的函数把距离场、二分、法线和阴影分开，让同一个距离估计可以被这些步骤重复调用。

噪声只生成一次，采用固定种子的 256×256 RGBA 数据；绿色通道相对红色通道平移，衔接原作三维噪声的相邻切片。采样显式使用 mip 0，避免分支内隐式导数带来的不确定性。天空和起步抖动使用它，分形几何不依赖这张纹理。

原作最后做亮度、饱和度、对比度、暗角和 `pow(..., 0.47)`。移植在非整数幂之前限制负值，防止产生 NaN，再把显示空间颜色解码回线性空间，交给站点统一输出 sRGB，避免重复提亮。极小的距离、半径和光源距离也有退化保护。

## 性能与使用

主要成本是重复的距离估计：每次步进要做九轮折叠，命中后还会查询二分、六点法线、两组阴影和颜色轨道。远处细孔也会有锯齿与闪烁；二分细化不能替代抗锯齿。移动视口使用模拟设备检查，不能当成真实手机性能。

本机 Ryzen 9 7950X3D / RTX 4080 SUPER、Chromium 151 上，桌面与模拟移动视口的 WebGPU、WebGL2 四组测量都先预热 3 秒，再记录 120 个 RAF 间隔：平均约 6.06 ms，P95 为 6.1–6.2 ms。这反映本机浏览器调度与显示环境，不是 GPU 时间。受控主线程负载下，自动 DPR 从 1 降到 0.8。

播放器默认 WebGPU，提供 WebGL2 后备、质量选择、自适应 DPR、减少动态效果时的静态海报，以及标签页隐藏时暂停。实际浏览器验证、本机帧间隔基线和验证边界记录在同目录 `VALIDATION.md`、`performance.json` 与 `browser-evidence.json`；帧间隔反映调度，不是 GPU 时间。
