## 先看见什么

蓝色宽带里套着细小折痕，浅青亮部像被压皱的玻璃，深蓝下缘逐渐隐入黑色。原作没有水体、光源、法线或反射；这张画面只需要十五行 GLSL。像素先改变自己的纵坐标，再用这个数值决定三种颜色分量。

同为 nasana 的「银纹流墨」逐次更新 x 和 y，再用正弦倒数制造灰度亮线。本例保留 x，只更新 y；每层使用两组正弦的乘积，最后直接读取高度形成彩色渐变。两者都属于坐标扭曲，这次适合练习**循环反馈、频率与幅度的区别，以及形状和颜色的分工**。它也没有「玫瑰噪流」里的随机哈希或 fBM。

## 一步一步拆开

### 1. 先铺一张纵向渐变

`uv()` 是覆盖画布的 0–1 坐标。先把中心移到原点，再按视口短边统一两轴的尺度：

```ts
const p = uv().mul(2).sub(1).mul(resolution).div(min(resolution.x, resolution.y)).toVar();
```

横屏里的 y 大致从 -1 到 1，x 的范围随宽高比扩展。竖屏的 y 范围更长，因此会看到更多上方的白色和下方的黑色。这是原作的取景方式。把「褶皱幅度」调到零，就能看见下面所有形变共同使用的蓝色渐变底图。

`toVar()` 让坐标成为可以写入的 GPU 变量。普通 TSL 节点描述一个表达式；循环要改变 y，需要保存每轮的结果。

### 2. 让两个方向的波相乘

每层先计算一个横向波和一个纵向波，再把它们相乘。横向波决定不同列往哪边推，纵向波让同一列的不同高度也有相反的位移。

```ts
const band = index.mul(index).mul(frequency);
p.y.addAssign(amplitude.mul(sin(p.x.mul(band).add(phase))).mul(sin(p.y.mul(band).add(phase))));
```

两个正弦都位于 -1 到 1 之间，所以一层位移的绝对值最多等于 `amplitude`。原作写成 `i * 0.1 / i`；由于层号从 1 开始，这个幅度始终是 **0.1**，不会随层号递减。移植把它写成可调的「褶皱幅度」，保留相同默认值。

### 3. 后一层读取前一层折过的坐标

层号为 1 到 7，频率依次为 1、4、9、16、25、36、49。较低频率先建立宽弯曲，后面的高频率在已经扭曲的 y 上继续折叠。

```ts
Loop({ start: int(1), end: int(layers).add(1), type: 'int', condition: '<' }, ({ i }) => {
  const index = float(i);
  // 用当前 p.y 计算位移，然后写回 p.y。
});
```

这七次更新在**同一个像素、同一帧**内完成，没有读取上一帧或其他像素。把七组波都放在原始 y 上计算再求和，会失去后续波跟随已有折痕的效果。

「层数」决定执行多少次反馈；「频率」共同放大每层波的变化速度。两者都能增加细节，但前者也增加运算次数。可先使用一层，再逐层增加，观察折痕怎样变得密集。

### 4. 把最终高度变成三种颜色分量

最终 y 直接加上三个不同偏移：

```ts
const height = p.y.add(colorOffset);
const displayRGB = clamp(vec3(height.sub(0.1), height.add(0.3), height.add(0.95)), 0, 1);
return sRGBTransferEOTF(displayRGB);
```

蓝色分量最先变亮，其次是绿色，最后才是红色。因此高度升高时，画面依次出现深蓝、蓝、青和白色。超出 0–1 的颜色在显示时会截到黑或白，这也解释了上下两端的大色块。

「色带位置」只在最后加一个偏移，不参与折叠计算；改变它时，颜色边界会移动，褶皱坐标本身保持相同。这里先解码显示空间 RGB，再交给共用渲染器输出 sRGB，避免额外的编码把颜色抬亮。没有加入玻璃折射或水面高光。

### 5. 让相位连续推进

原作两组正弦都使用 `iTime * 0.5`。本站默认从原作第 7 秒开始，再用时间乘以「流动速度」：

```ts
const phase = float(context.time as unknown as number)
  .mul(speed)
  .add(7)
  .mul(0.5);
```

暂停会冻结当前形状；恢复默认参数会回到固定初始相位，便于比较。海报来自实际 TSL 画布；短片用较慢速度录制，再接倒放闭合循环。这种往返只用于预览素材，交互画布正常向前推进。

## 性能观察

默认每个像素执行七轮，每轮计算两个正弦，没有贴图读取或射线步进。层数增加会直接增加每帧运算；频率升高不会增加循环次数，却可能让一条折痕窄于一个像素。特别是在层数与频率同时调高时，可用固定画质观察锯齿，不要把更细密误认为更高质量。

画布复用本站的自适应 DPR、隐藏暂停和减少动态策略。本机四组桌面/移动、WebGPU/WebGL2 的 120 个 RAF 间隔平均均为 6.06 ms，P95 为 6.1–6.2 ms；这只是浏览器调度观察，不等于 GPU 时间或真实手机性能。受控每帧 45 ms 主线程负载使自动 DPR 从 1 降到 0.8；它验证调整响应，不是这份 shader 的自然负载。

减少动态会先显示海报，主动播放后才启动渲染；受控隐藏事件能停止并恢复 GPU 提交。原生后台标签页仍报告 `document.hidden=false`，所以实际后台暂停路径未验证通过，不能把受控测试当成原生结果。原作对照、媒体和完整边界见 `VALIDATION.md`。
