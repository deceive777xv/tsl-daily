## 原作与后端对照

`reference-comparison.json` 记录同一 Chromium、1440×900、源时间 2 的对照。完整唯一 Image pass 未改动，实际执行的 GLSL 字符串与镜像解码字符串相同；GL 与 readPixels error 均为 0，无页面错误或控制台错误、警告。

- 原始 GLSL → TSL WebGL2：RGB 平均字节绝对差 **0.0001975309/255**，最大 **128/255**。较大差异仅占 **2 个像素**，坐标 `(1365,139)`、`(1079,786)`。
- WebGPU → WebGL2：平均 **0.0000987654/255**，最大 **128/255**。较大差异仅占 **1 个像素**，坐标 `(1431,717)`。
- 这些像素的灰度在 127 与 255 之间选择了不同的面。画面整体经视觉对照吻合；推测与离散边界处浮点比较有关，不宣称已确定根因，也不宣称逐像素完全一致。最大误差和完整坐标均保留，未用平均值掩盖它们。
- 默认占用公式、相机、三档灰度、并列推进和面优先级保留。移植新增有限分母保护、掩码初始化、数值 `step` 掩码及命中提前结束；原始 GLSL 本身没有修改。

奇数绘制尺寸 **401×701** 让一整行射线的 y 分量正好为零；两后端实际运行后，该行均为有效面灰度，异常像素 **0**，没有 NaN 导致的黑线。另以体素 0.5、焦距 0.5、挖空 10、对比 1.5 的组合进行 smoke，两后端无错误或警告。该组合仍受 64 次遍历预算限制，不把它称为所有像素的精确几何验证。

## 本机性能基线

Windows，CIM 当次核验 AMD Ryzen 9 7950X3D / NVIDIA GeForce RTX 4080 SUPER，另有 AMD 集成显卡。每组默认自动画质暖机 3 秒，顺序采集 120 个 RAF 间隔；这是 **浏览器调度观察，不是 GPU 时间戳，也不是真实手机性能**。

| 视口             | 实际后端 | 绘制尺寸 | 有效 DPR | 平均 / P95    |
| ---------------- | -------- | -------- | -------- | ------------- |
| 桌面 1440×900    | WebGPU   | 1440×900 | 1        | 6.06 / 6.2 ms |
| 桌面 1440×900    | WebGL2   | 1440×900 | 1        | 6.06 / 6.1 ms |
| 移动模拟 412×915 | WebGPU   | 618×1372 | 1.5      | 6.06 / 6.1 ms |
| 移动模拟 412×915 | WebGL2   | 618×1372 | 1.5      | 6.06 / 6.2 ms |

四组横向溢出均为 0，无外部请求或页面/控制台错误。每帧受控增加 45 ms 主线程负载、持续 130 帧后，自动 DPR **1 → 0.8**。它验证画质策略响应，不是自然 shader 负载测量。DDA 最多查询 64 次，命中可提前结束；细网格可能先耗尽预算，不能仅凭 Branchless 名称推断比其他方法更快。

## 减少动态与隐藏暂停

- `prefers-reduced-motion: reduce` 下初始 backend 为空，静态海报已加载；主动播放后启动实际 WebGPU，按钮为“暂停动画”。
- 受控设定 `document.hidden=true` 并触发 visibilitychange 后，GPU submits 在 800 ms 内 **482 → 482**；恢复后为 **618**，按钮与状态同步。暂停/恢复处理路径通过。
- **原生后台标签页行为仍未验证通过**：真实切换到另一标签页时 Chromium 仍报告 `document.hidden=false`；submits **378 → 378**，返回后为 **478**。提交暂时稳定不能在 Page Visibility 没有报告隐藏时证明原生隐藏路径通过。此结果与受控事件分开保存，不混用。
