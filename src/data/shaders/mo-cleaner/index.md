## 先看见什么

白色的小机器人弯着身子擦地，手臂带动滚刷，头顶的红灯和窄窄的黄眼睛让它显得很专注。地砖、污迹和墙灯沿身后流动，机身也随路径轻轻转动，构成“正在向前清扫”的感觉。

作者把它称为对 Pixar《Wall-E》中 M-O 的致敬。这里没有导入角色网格、贴图或动画文件；全部形体、地面纹理和动作来自一个 Image pass。已有「熔彩流动」用平滑并集融合抽象球体；这次把距离场当作一盒零件，通过局部坐标、材质编号和相互关联的角度装出有动作的角色。

## 一步一步拆开

### 1. 找到最近的零件，也记住它是什么

方盒、圆柱、球和渐细截面各自返回一个距离。用 `min` 选最近值，就能把它们放进同一个场景。但着色时还需要区分眼睛、外壳和刷头，因此每次选中距离，也一起保存材质编号与局部纹理坐标。

```ts
const hit = vec4(abs(p.y), 1, p.xz).toVar();
const candidate = vec4(distance, id, texturePoint).toVar();
If(candidate.x.lessThan(hit.x), () => {
  hit.assign(candidate);
});
```

这里用 `vec4` 打包 `(距离, 材质编号, u, v)`，对应原作的 `Hit` 结构。编号是可以精确表示的小整数；它只用于选材质，没有被当作连续颜色插值。每个候选先 `.toVar()`，把这一刻的坐标保存下来，避免后续关节变换改变已经命中的纹理位置。

机身由略带圆角的盒体构成，刷头是沿 x 轴的圆柱，两侧手臂用渐细截面切出轮廓。眼睛、条纹和刷毛细节大多通过材质或三角函数产生，无需为每一道纹理增加几何体。

### 2. 旋转坐标，让零件绕关节运动

距离函数常在“零件位于原点”的局部空间里最简单。要让零件转动，可以先反向变换采样点，再查询同一个距离函数。原作依次改变躯干、手臂和头部使用的坐标，因此一个角度会带动多个部位。

```ts
p.yz.assign(rotate(p.yz, motion.y.negate()));
p.y.subAssign(1.7);
const bodyPoint = p.toVar();
p.y.subAssign(0.5);
p.yz.assign(rotate(p.yz, motion.y.negate()));
```

先旋转、再平移，与先平移、再旋转会得到不同的支点。`bodyPoint` 保存躯干空间，头部从它重新开始变换，避免继承刷头的位移。

本例特意保留原作 `p *= mat2(c,s,-s,c)` 的行向量方向：`(x*c + y*s, y*c - x*s)`。照搬另一种矩阵乘法顺序会让动作朝反方向走。「关节幅度」同时缩放这些角度；降为零，可以看见角色组装时的基础姿态。

### 3. 用距离走向表面，再从邻近查询估计朝向

每个像素发出一条射线，最多查询 110 次。离表面远就走大步，接近后缩小步子；当距离绝对值小于 `0.0015`，便在最后一个点着色。原作保留了有符号步长，本移植也没有擅自改成固定小步或额外添加远距离裁切。

```ts
p.assign(ro.add(ray.mul(travel)));
hit.assign(field(p, motion));
glow.addAssign(glowAt(p, motion.x));
If(abs(hit.x).lessThan(0.0015), () => {
  Break();
});
travel.addAssign(hit.x);
```

命中点附近再沿四个四面体方向查询距离，估计梯度并归一化，得到表面法线。它决定朝向灯光的亮度、阴影采样方向和反射方向。零长度梯度有显式保护；原始 GLSL 快照保持不变。

原作每个像素取四个子像素样本，缓解细刷毛和眼睛条纹的锯齿。移植保留这四次采样及其顺序，因而默认效果比单次步进更贵。

### 4. 把轮廓变成外壳、眼睛和阴影

材质编号把同一个命中位置分配给不同规则：外壳为白色并带黑条，刷头偏黑，顶灯为红色，脸部局部坐标里切出两只黄色眼睛。先按命中编号取颜色，再修改地面法线，最后叠加直接光、近似反弹光、高光、软阴影与环境遮蔽。

```ts
const shade = shadow(point, light, motion).toVar();
const occlusion = mix(
  field(closePoint, motion).x.div(0.3),
  field(farPoint, motion).x.div(2),
  0.7,
).toVar();
```

软阴影从表面沿光方向再走最多 20 步；环境遮蔽只在法线方向取两个固定距离样本。这些都是控制成本的近似。「软阴影浓度」能单独关闭阴影，让你分辨阴影与环境遮蔽各自带来的立体感；后者不会随这个参数关闭。

原作 `map()` 每次执行都会累加墙灯辉光，包括法线、阴影、遮蔽和反射里的查询，甚至会传到下一个抗锯齿样本。本例把它拆为纯距离查询和 `glowAt()`，显式返回累计值，避免把这些副作用藏在跨后端的全局变量里。它仍是原作的经验性发光效果，不是能量守恒的体积光积分。

### 5. 移动地面，让清扫产生方向感

角色没有在无限大的模型场景中前进。地面纹理坐标随时间移动，正弦路径让角色左右偏移；地砖线、散点污迹和清扫轨迹共同建立速度感。命中地面后还会发出第二条反射射线，最多 90 步，取反射物的材质颜色混合进地面。

「地面反射」默认只有原作的 `0.01`。把它调大，可以看清反射的来源，也会发现这不是完整的物理反射：第二次命中只取材质，没有再计算完整光照。即使调为零，仍保留这段射线查询，以维持原作辉光累加的顺序；这个参数不用于减少循环次数。

「取景范围」只缩放相机平面，数值越大视野越宽。窄屏会自动扩展取景并向角色轻微平移，让机器人保持完整可见；桌面默认保留原作构图。「清扫速度」同步推进所有动作；零值固定在原作第 2 秒。每 30 秒时间取模一次，包含原作的动作重置，因此素材采用短段往返剪辑，不把它描述为原作天然无缝循环。

## 性能与验证边界

主要开销是四次子像素采样，以及每次采样中的主射线、法线、软阴影、遮蔽和地面反射。一个参数使画面变化更小，并不等于 GPU 少执行了查询。优先调低画质或使用自动 DPR，再观察细线与轮廓的清晰度。

默认使用 WebGPU；浏览器不支持时退回 WebGL2。减少动态偏好下先显示海报，手动播放才启动渲染。桌面与移动视口、两种后端、五个参数、来源对照和本机调度基线见同目录 `VALIDATION.md`、`performance.json` 与 `browser-evidence.json`。移动视口模拟不代表真实手机性能。

原生后台标签页状态受当前浏览器自动化环境限制，必须以验证档案中的实际观察为准。受控 `visibilitychange` 的暂停/恢复结果不能证明原生隐藏标签页已经通过验证。
