## 先看见什么

一个金色方块浮在柔和的背景里。大方孔穿透内部，小方孔又出现在大孔之间；相机绕行时，洞壁的紫红色、深处的阴影和再次出现的小孔，让它像一座没有模型文件的微型城市。随后，孔洞会被旋转、错位，方块暂时变成复杂的切割结构。

这就是 Menger Sponge 的有限层数距离场版本。屏幕上只有一个覆盖视口的平面，立体形状由每个像素里的数学查询产生。已有「星巢」把分形活动量积累成发光体积；这里的重点是**怎样从实体方块中减去一组不断缩小的孔洞**。

## 一步一步拆开

### 1. 先描述一个方块，再限定搜索范围

把待查询点的每个坐标取绝对值，减去方块半边长 1：`abs(p) - 1`。在内部，最大的分量表示离最近面的有符号距离。原作把它与正分量的长度取最小值：

```ts
const edge = abs(point).sub(1);
const largest = max(edge.x, max(edge.y, edge.z));
return min(largest, length(max(edge, 0)));
```

负值表示点在实体内部，正值表示点在外面。这个原作写法在外部棱角处可能低估欧氏距离，并非处处精确的立方体 SDF；移植保留它作为步进距离估计。切割前，它描述一个没有孔的实心方块。

相机发出的视线先与半边长 1.05 的包围盒求交，得到进入和离开的距离。射线步进从进入处开始，越过离开处就结束。最终形状始终受原方块限制，所以这里可以跳过大段空背景；包围盒不会替我们找到内部表面。

### 2. 用十字切割做一次挖孔，再把它重复三倍

一次切割可以看成沿三个坐标轴贯通的方形通道。两两取最大值描述一个通道的横截面，再对三个结果取最小值，把三条通道合成十字。

每一层先把坐标乘上 `scale`，用 `mod(..., 2) - 1` 折回重复单元，再把尺度乘 3。计算出的切割距离最后除以新尺度，换回世界单位。大孔、中孔、小孔因此复用同一套运算。

```ts
const cell = mod(point.mul(scale), 2).sub(1).toVar();
scale.mulAssign(3);
const r = abs(vec3(1).sub(abs(cell).mul(3)));
const xy = max(r.x, r.y);
const yz = max(r.y, r.z);
const zx = max(r.z, r.x);
const cut = min(xy, min(yz, zx)).sub(1).div(scale);
distance.assign(max(distance, cut));
```

这里的 `cut` 已经带上用于“挖去”的符号方向，所以对实体距离取 `max` 就得到差集；不是把两个实体并在一起。`toVar()` 在尺度乘 3 前保存当前单元坐标；TSL 节点描述待生成的表达式，不等于立即求值的 JavaScript 数字。四层只是一种有限近似，没有真的生成无限多的孔，也没有创建递归 JavaScript 对象。

「分形层数」从 1 到 4 改变循环的有效层数。先停在一层看清大孔，再逐层增加，比一开始只盯着最细的纹理更容易理解构造。

### 3. 变形发生在查询坐标里

原作在每一层挖孔前，把当前点与旋转、平移后的点混合。相机和外方块不必一起旋转；孔洞的查询空间改变后，它们自然错位。

```ts
const shifted = point.add(offset).toVar();
const turned = vec3(
  shifted.x.mul(0.6).sub(shifted.z.mul(0.8)),
  shifted.y,
  shifted.x.mul(0.8).add(shifted.z.mul(0.6)),
);
point.assign(mix(point, turned, morph));
```

这三行点积对应 GLSL 列主序矩阵 `ma * (p + off)`。如果当成行向量旋转，变形方向会反过来。

原作的混合量来自时间上的余弦与 `smoothstep`，在规则孔洞和完全变形之间往返。新增「变形偏置」把这个混合量再向 1 拉近；0 保留原节奏，1 持续使用完全变形。它不是物体的整体旋转角度。

### 4. 用步进找表面，让构造同时提供层级信息

在包围盒内最多查询 64 次，每次按当前距离推进。距离小于 0.002 时结束；原作保留的是最后一次收敛前的位置与材质记录，移植保持这一细节。超过预算并不等于证明已经找到精确交点，有限层数、阈值和变形仍是视觉近似。

距离函数除了返回距离，还记录哪一层切割成为当前边界，以及从三个通道距离乘积得到的遮蔽量。这样一次查询可以同时决定形状、层级配色和暗处的程度。

「调色相位」移动 `0.5 + 0.5 * cos(...)` 中的相位。它改变颜色而不改孔洞的位置；层级数据仍负责让不同尺度的洞壁获得不同颜色。

### 5. 用法线、遮蔽和软阴影交代孔洞深处

在交点的 x、y、z 两侧各查询一次距离，用六个样本的差值估算法线。法线告诉我们表面朝向；太阳漫反射照亮外壁，冷色天空和近似反弹光补亮背面。

软阴影另发一条朝太阳的射线，把沿途的 `k * h / t` 最小值积累下来：`h` 是离实体的距离，`t` 是离起点的距离，`k` 是锐度。靠近遮挡物会降低结果，接近完全遮挡或离开包围盒就提前结束。

```ts
shadow.assign(min(shadow, sharpness.mul(distance).div(travel)));
travel.addAssign(clamp(distance, 0.005, 0.1));
```

「阴影锐度」越小，暗部过渡通常越宽；它是距离比启发式，不是实际面积光源的半径。构造得到的遮蔽量也不是另外积分得到的物理环境遮蔽。它们共同帮助读者辨认洞壁和深处，同时控制查询次数。

## 试着调一调

| 参数     | 可以观察什么                                              |
| -------- | --------------------------------------------------------- |
| 动画速度 | 相机绕行与挖孔坐标变形的共同时间倍率；0 回到源时间第 2 秒 |
| 分形层数 | 1 层大孔如何逐步长成 4 层细孔；也影响每次距离查询的成本   |
| 变形偏置 | 查询坐标向旋转结果混合后，规则孔洞怎样错位                |
| 调色相位 | 几何不变时，层级材质与余弦颜色如何分工                    |
| 阴影锐度 | 小孔和背面阴影的边缘怎样变宽、变窄                        |

默认从原作第 2 秒开始，使用原作的四层几何和单采样分支。为控制实时成本，没有使用原作高性能分支的 2×2 像素超采样；高画质提高画布分辨率，不能把它当作完全等价的四次采样。预览短片的往返播放只用于闭合媒体循环，实时动画仍向前运行。原始 GLSL 中的 `mainVR` 完整归档，本站使用普通二维视口。

## 性能与运行边界

每次距离查询最多执行四层切割，主射线与阴影各最多 64 次查询；法线另用六次查询。循环能提前结束，但细孔、复杂变形和高分辨率仍会增加成本。降低分形层数减少每个查询里的运算，降低画质减少整幅图的像素数，两者改变的是不同部分。

站点默认 WebGPU，也提供 WebGL2 后备；减少动态效果时先显示静态海报，读者可以主动播放。自动画质根据连续帧间隔调整 DPR。隐藏事件的暂停路径与原生后台标签页验证分开记录；本机浏览器切换标签后若仍报告 `document.hidden=false`，就不能宣称原生后台暂停已经验证。

2026-10-09 在 Windows、Ryzen 9 7950X3D / RTX 4080 SUPER、Chromium 151 上，桌面 1440×900 与移动模拟 412×915 的 WebGPU / WebGL2 四组默认运行，暖机 3 秒后各采样 120 个 RAF 间隔：平均均约 6.06 ms，P95 为 6.1–6.2 ms；移动有效 DPR 为 1.5。受控主线程负载下，自动 DPR 从 1 降到 0.8。这是 RAF 调度观察，不是 GPU 时间戳，也不代表真实手机速度。

非后备 `nvidia / lovelace` WebGPU adapter、完整基线和控制事件见同目录 `performance.json`、`browser-evidence.json` 与 `VALIDATION.md`。本机原生标签切换仍报告 `document.hidden=false`，因此只验证了受控隐藏事件的暂停与恢复，没有验证原生后台暂停。
