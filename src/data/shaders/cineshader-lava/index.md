## 先看见什么

圆润的球团缓慢移动，靠近时拉出柔软的连接，分开时又回到独立的轮廓。颜色在表面流过，明暗让球团看起来有厚度。像熔岩灯，也像一块持续揉动的彩色软糖。

这里没有球体网格，也没有流体模拟。每个像素沿着一条射线询问：“我离形体还有多远？”十六个球体的距离经过平滑融合，便构成整个场景。和八角回廊相比，重点从重复的硬边几何转向形体之间的连接；和星巢相比，这次寻找的是实体表面，而非沿途累加体积光。

## 一步一步拆开

### 1. 用一个数字描述球体

球心在原点、半径为 `r` 的球，可以写成 `length(p) - r`：球外为正，表面为零，球内为负。我们无需预先生成顶点，就能在任意位置查询这个距离。

```ts
const radius = mix(0.5, 1, fract(fi.mul(412.531).add(0.5124))).mul(settings.z);
const sphereDistance = length(p.add(offset)).sub(radius);
```

`fi` 是球体编号。`fract` 取小数部分，为每个编号产生固定但不同的半径与运动速度；它不是每帧重新抽取随机数。`sin` 让球心在三个方向上往返，其中深度方向的幅度更小，因此形体主要在屏幕平面展开。原作写作 `p + offset`，对应的球心实际上位于 `-offset`。

“形体速度”控制时间，“球体大小”控制半径。先固定时间再调大小，就能把形态变化与运动分开观察。

### 2. 把相交边缘揉圆

两个距离直接取 `min(a, b)` 可以求并集，但相交处往往有明显折痕。平滑并集在两个距离接近时，混合它们并稍微降低距离值，从而填平连接处。

```ts
const h = clamp(float(0.5).add(b.sub(a).mul(0.5).div(k)), 0, 1);
return mix(b, a, h).sub(k.mul(h).mul(float(1).sub(h)));
```

`k` 是融合范围。当两个距离差得很远，`h` 会被夹到 0 或 1，结果回到较小距离；接近时，末尾的减项把表面向外推，长出连接。把“融合程度”降到最小，可以看清单个球；逐渐增加，就会看到圆滑的颈部。

场景以距离上限 2 开始，依次合并十六个球。球数固定，因此调整大小或融合程度不会改变球体循环次数。但融合后的距离不应被简单理解为任何情况下都精确的欧氏距离；步进仍需要停止阈值与最大次数。

### 3. 沿平行射线寻找表面

原作使用正交投影：每个像素的起点不同，方向都为 `(0, 0, -1)`。默认横屏保持原作按屏幕高度覆盖六个世界单位的比例；竖屏按宽度容纳六个单位，避免球团左右被大幅裁掉。

```ts
point.assign(origin.add(vec3(0, 0, depth.negate())));
const distance = field(point, settings).toVar();
If(distance.lessThan(0.001), () => {
  Break();
});
depth.addAssign(distance);
If(depth.greaterThanEqual(6), () => {
  depth.assign(6);
  Break();
});
```

每一步按估计距离前进，靠近表面时步子自然缩小。最多走 64 步；足够接近则命中，超过六个单位则退出。走满步数但尚未到远端的擦边像素，仍在最后采样点估计表面法线，以避免突然变暗；这是一种近似，不代表精确求交。这和“每次前进同样距离”的采样不同，可以跳过大片空白。

`.toVar()` 保存本步的距离。TSL 表达式是着色器计算图，如果一个表达式依赖随后会修改的变量，就需要明确保存取值，才能保持预期的执行顺序。`Loop`、`If`、`Break` 在 GPU 上执行，JavaScript 只负责构建程序。

### 4. 从距离变化估计法线

命中后，还需要知道表面朝向。法线可以理解为距离增长最快的方向。沿四个四面体方向各取一次距离，把这些方向按距离值加权相加，就能近似得到梯度。

```ts
const gradient = k.xyy
  .mul(field(p.add(k.xyy.mul(0.001)), settings))
  .add(k.yyx.mul(field(p.add(k.yyx.mul(0.001)), settings)))
  .add(k.yxy.mul(field(p.add(k.yxy.mul(0.001)), settings)))
  .add(k.xxx.mul(field(p.add(k.xxx.mul(0.001)), settings)));
return gradient.div(max(length(gradient), 0.000001));
```

其中 `k = vec2(1, -1)`。把法线和固定光方向点乘，得到亮度 `b`：朝向光的一侧更亮，背向光的一侧取零。这里没有阴影射线、反射或真实材质模型，立体感主要来自这一项。

本改编把法线采样间距从 `1e-5` 增至 `0.001`，降低两后端浮点相减的误差；没有命中的背景直接使用零亮度，不再归一化零梯度。这会带来细微的表面明暗差异，原始 GLSL 保持不变供对照。

### 5. 让颜色独立流动

原作将亮度、时间和屏幕坐标一起送入余弦函数，三个颜色通道分别错开相位，生成连续变化的调色板。

```ts
const phase = brightness.add(elapsed.mul(colorSpeed).add(8).mul(3));
const color = cos(phase.add(screen.xyx.mul(2)).add(vec3(0, 2, 4)))
  .mul(0.5)
  .add(0.5)
  .mul(brightness.mul(0.35).add(0.85))
  .mul(exp(depth.mul(attenuation).negate()));
```

余弦范围是 `[-1, 1]`，缩放并平移后变成 `[0, 1]`。表面亮度同时影响色相与强度，深度则用指数衰减压暗远处。“色彩速度”和“形体速度”各自独立：可以让物体不动而颜色流动，也可以固定颜色循环观察形体运动。“景深衰减”只是距离造成的明暗变化，不是摄影中的景深模糊。

## 可以亲手试什么

- **形体速度**：设为零，观察固定形状上的颜色变化。
- **融合程度**：先调低，再提高，观察相邻球之间如何长出连接。
- **球体大小**：在暂停状态下改变半径，看相同位置的球团何时接触。
- **色彩速度**：与形体速度分开调节，区分几何运动和颜色动画。
- **景深衰减**：设为零再恢复，比较背景与前景的层次。

暂停后参数仍可调整；恢复默认参数会重置时间。默认从原作第 8 秒开始。本案例不使用指针位置，移动端仍可滑动切换案例。

## TSL 重写要点

`Fn().setLayout()` 将距离函数编译成可复用的 WGSL / GLSL 函数；球体距离与时间等参数通过显式输入传入。画布依旧使用站点的全屏平面，实际的三维形体完全来自片元计算。

原作 Alpha 通道记录供 CineShader 使用的厚度信息，不是透明度。本案例展示其 RGB 画面并使用不透明输出，不接入 CineShader 的模型或厚度处理。未命中的背景、远端退出和法线保护使数值行为更明确；增加的五个参数和竖屏适配属于改编。

颜色按原作显示 RGB 解释，先限制到 `[0, 1]`，经 `sRGBTransferEOTF` 解码后再由运行时编码输出，避免重复颜色转换使画面变白。

## 性能观察

最坏情况下，每像素执行 64 次距离查询，每次合并 16 个球；命中后再用四次查询估计法线。背景超过远端会提前退出，命中表面的像素也通常不必走满 64 步。主要成本是片元数量、距离查询与三角函数，而不是顶点数量。

调节融合与大小会改变命中位置和实际步数，不能只凭球数固定就断言开销不变。运行时沿用自适应 DPR、隐藏标签页暂停和减少动态效果时的静态海报。移动视口会扩大可见范围，更多区域可能是提前退出的背景；桌面模拟手机不能替代实体手机性能。2026-09-12，本机 Ryzen 9 7950X3D / RTX 4080 SUPER、Chromium 153.0.8010.37：生产页面预热 3 秒后采样 120 个 RAF 间隔，桌面与移动视口的两后端平均均为 6.06 ms，p95 为 6.10–6.20 ms。它是帧调度间隔，不是 GPU 执行耗时。负载下 DPR 从 1 降至 0.8。受控隐藏事件可停止 GPU 提交；真实后台标签在本机自动化环境仍报告 visible，因此实机隐藏路径未验证。完整记录见同目录 VALIDATION.md。
