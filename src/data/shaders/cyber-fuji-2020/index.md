## 先看见什么

一轮被横条切开的粉色落日，一座覆雪的山，几朵像霓虹灯管勾出的云。下方网格向远处收拢并持续前进，让平面的风景有了驾驶途中望向远山的感觉。

这幅画没有三维山体、相机或光照系统，也没有纹理。每个像素只计算自己到几种二维图形的距离，再决定该用哪一层颜色。与真实海面或分形空间相比，这个案例更适合观察：如何用少量形状，把画面组织成一个完整场景。

## 一步一步拆开

### 1. 先划分天空与地面

屏幕坐标以画面中心为原点，按高度归一化，让圆在宽屏上仍然是圆。`y = -0.2` 是地平线：其下计算网格，其上组合太阳、山和云。

```ts
const depth = float(3).div(abs(p.y.add(0.2)).add(0.05));
const gridUV = vec2(p.x.mul(depth), depth)
  .mul(density)
  .add(vec2(0, time.mul(4.2)));
```

越靠近地平线，分母越小，采样坐标越大。因此相同的网格单位被压进更少的屏幕像素，产生透视感。`0.05` 避免地平线处除以零，也限制远处的压缩程度。时间只沿网格纵向推进，不移动真正的几何体。

竖屏额外放宽采样范围，保持太阳与山同时可见；上下会显示更多天空和地面。这是针对阅读设备的构图适配，宽屏默认保持原作坐标。

### 2. 用重复坐标画发光网格

`fract(gridUV)` 把连续平面折回每个单元，减去 `0.5` 后，单元中心成为零。分别计算 x、y 两个方向的软线，再相加，就得到横纵交织的格子。

```ts
const cell = abs(fract(gridUV).sub(0.5));
const core = vec2(1).sub(smoothstep(vec2(0), size, cell));
const halo = vec2(1).sub(smoothstep(vec2(0), size.mul(5), cell));
```

较窄的遮罩是亮线，较宽的遮罩是光晕。原作让线宽随深度变化，远处格子逐渐融成明亮的带状区域；这里保留这种风格。它不是后处理 Bloom，也不模拟光能传播。提高网格密度不会增加绘制次数，但更细的网格可能闪烁。

### 3. 从圆里切出条纹落日

到太阳中心的距离决定圆盘和外围柔光；竖直坐标经过正弦函数，形成周期性横条。另一个随高度变化的偏置，让上方圆盘更完整、下方裂隙更明显。

```ts
const cut = clamp(
  sin(sunUV.y.add(time.mul(0.204)).mul(stripes))
    .mul(3)
    .add(clamp(sunUV.y.mul(14).add(1), -6, 6)),
  0,
  1,
);
```

圆盘遮罩乘以条纹遮罩，表示“既在圆内，又属于亮条”。圆外光晕单独相加，所以切开的暗条并不会把所有柔光一同切掉。“落日条纹”参数直接控制正弦频率，可以观察图案频率与视觉节奏的关系。

### 4. 给梯形穿上山体与雪线

山体以梯形距离场为基础：距离为负表示内部，零表示边界。原作让梯形底部宽度随采样高度变化，形成向两侧展开的山脚，因此它并非固定梯形的精确距离场。这里仅用其符号与窄边界画图，不用它驱动 Ray Marching。

山体颜色从深蓝渐变到粉色；雪线则是一条被正弦函数扰动的高度阈值：

```ts
const wave = p.y.add(sin(p.x.mul(20).add(time.mul(2))).mul(snow)).add(0.2);
const snowMask = smoothstep(0, 0.01, wave).mul(inside);
```

乘以 `inside` 后，雪只落在山的轮廓内。把雪线起伏设为零，先看水平分界，再逐渐加大振幅。山边缘另用 `abs(distance)` 生成细描边；颜色分层和边缘强调一起让简单形状变得鲜明。

### 5. 用线段和平滑并集拼出云

每朵云由两条水平线段和一块连接区域组成。线段距离通过投影计算，投影参数限制在 `[0, 1]`，所以两端自然形成圆头。原作将这些距离通过平滑并集连接，避免连接处出现生硬的凹角。

```ts
const h = clamp(float(0.5).add(b.sub(a).mul(0.5 / 0.05)), 0, 1);
return mix(b, a, h).sub(h.mul(float(1).sub(h)).mul(0.05));
```

先根据云的内部遮罩覆盖深蓝色，再沿固定距离等值线加亮描边。云朵用 `mod` 沿水平方向循环，端点各自轻微摆动，形状也在呼吸。最后把地平线柔光叠入全画面，再混入少量灰度，得到统一的复古色调。

## 可以亲手试什么

- **流动速度**：同时改变网格、条纹、雪线和云朵的时间速度；零值停在初始构图。
- **网格密度**：比较近处格子大小、远处融合与像素闪烁。
- **落日条纹**：观察同一个圆形如何因遮罩频率而改变节奏。
- **雪线起伏**：在水平雪线与波浪雪线之间比较。
- **霓虹辉光**：关掉太阳、云边、网格与地平线的附加柔光，再逐步恢复。

暂停后仍可调整参数，恢复默认值会同时重置时间。本案例不使用指针位置；移动端保留站点的滑动切换操作。

## TSL 重写要点

`Fn().setLayout()` 把距离函数编译为可复用的 WGSL / GLSL 函数，`If` 在 GPU 上选择天空或地面分支，`.toVar()` 与 `.assign()` 表达有顺序的颜色叠加。TSL 中的节点运算构建着色器，不是在 JavaScript 每帧逐像素运算。

原作多处使用反向边界的 `smoothstep`。本改编统一转为 `1 - smoothstep(较小值, 较大值, x)`，避免依赖 GLSL 未定义行为。线段投影分母增加极小值保护。时间从原作第 8 秒开始；原始 GLSL 快照不作修改。原作固定为 1 的 `battery` 保持固定，其实验性鼠标分支不启用。

原作颜色按显示 RGB 解释，先截断至 `[0, 1]`，用 `sRGBTransferEOTF` 解码，再交由站点运行时编码输出。这保留原作有意明亮的雪顶和地平线，不把它误解释为物理光照。双后端浮点计算可能造成很细的网格边缘差异。

## 性能观察

每个像素只处理二维坐标、少量三角函数、距离和遮罩，没有纹理读取、Ray Marching 或逐帧几何上传。网格密度和条纹数改变视觉频率，不改变循环次数。窄屏为保留构图扩大坐标范围，也不增加几何数量。

运行时沿用自适应 DPR、隐藏标签页暂停与减少动态效果时的静态海报。原作地平线处线条很密，低分辨率下可能出现摩尔纹；可降低网格密度或提高画质。具体双后端浏览器、性能和媒体检查结果见同目录 VALIDATION.md。

2026-09-09，本机 Ryzen 9 7950X3D / RTX 4080 SUPER、Chromium 153.0.8010.37，生产页面预热 3 秒后采样 120 个 RAF 间隔：1440 × 900（DPR 1）和 412 × 915（DPR 1.5）下，WebGPU / WebGL2 平均均为 6.06 ms，p95 为 6.10–6.20 ms。它是帧调度间隔，不是 GPU 执行耗时；移动视口仍用桌面 GPU，不能代替真机性能。注入约 45 ms/帧主线程负载后，画布 DPR 从 1 降至 0.8。受控隐藏事件的暂停和恢复通过；自动化浏览器切换标签后仍报告 visible，真实后台状态未得到验证。
