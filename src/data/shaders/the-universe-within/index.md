## 先看见什么

光点并不是孤立地飘动：它们被细线连接成不断舒展的三角形和四边形，有些节点突然亮起，又渐渐隐去。近处的结构向画面边缘扩张，远处还有更细的一层，像穿行在星座之间，也像从内部观察一张巨大的神经网络。

这里没有粒子缓冲区、三维网格或物理弹簧。每个像素只需询问附近九个节点的位置，计算自己离连线和光点有多远，再把四张二维网络叠起来。空间感来自层次的运动关系。

本案例只改编视觉。原作另有音乐输入，本页不请求或播放音乐；原先受音频驱动的背景亮度可以直接通过参数调整。

## 一步一步拆开

### 1. 给每个格子一个会摆动的节点

用 `floor(st)` 得到整数格子编号，用 `fract(st) - 0.5` 得到当前格子内的坐标。编号经过哈希函数后产生稳定的伪随机数：相同格子每次获得相同结果，时间推进也不会重新抽签。

从一个随机数分出两种频率，让节点在格子中心附近分别沿 x 和 y 摆动。位移幅度限制在 `0.4`，因此节点不会任意飞走，网络仍然保持局部结构。

```ts
const n = hash(id.add(offset));
const phase = time.add(n);
return offset.add(
  vec2(sin(phase.mul(fract(n.mul(10)))), cos(phase.mul(fract(n.mul(100))))).mul(0.4),
);
```

`offset` 从 `(-1, -1)` 到 `(1, 1)`，共九个位置。这样每个像素都知道当前格子及周围八个格子的节点在哪里，不需要在 CPU 上维护节点数组。TSL 中生成九个表达式的 JavaScript 循环只在构建 Shader 时执行。

### 2. 用到线段的距离画出连接

要连起 a、b 两点，先把像素到 a 的向量投影到 `b - a` 上。把投影系数限制在 `[0, 1]`，就能找到线段上离像素最近的点；像素与这个点的距离决定线条覆盖率。

```ts
const segment = b.sub(a);
const relative = p.sub(a);
const h = clamp(dot(relative, segment).div(max(dot(segment, segment), 0.000001)), 0, 1);
const distance = length(relative.sub(segment.mul(h)));
```

`1 - smoothstep(width * 0.25, width, distance)` 把距离变成柔和的线条。原作还根据线段长度调节亮度：过长的连接逐渐消失，接近特定长度的连接获得额外亮度。最后补上四条邻居之间的边，让画面不只是一簇簇放射状星形。

这里计算的是二维线段距离，不需要 Ray Marching。原作循环包含中心节点到自身的零长度连线；改编跳过这条边，并保护投影分母，避免 `0 / 0`。

### 3. 让节点在适当时刻闪一下

节点辉光与距离平方的倒数成正比，所以中心很亮，稍远处迅速衰减。再把缓慢变化的正弦信号提升到 20 次幂：大多数时刻接近零，靠近峰值时才形成短促闪光。

```ts
const pulse = sin(fract(points[i].x).add(fract(points[i].y)).add(time).mul(5))
  .mul(0.4)
  .add(0.6);
sparkle.addAssign(
  float(0.005)
    .div(max(d.mul(d), 0.0001))
    .mul(float(1).sub(smoothstep(0.7, 1, d)))
    .mul(pow(pulse, 20)),
);
```

分母的极小值保护限制了中心峰值。它仍然是艺术化的加法辉光，没有使用 Bloom 后处理，也不是物理准确的光源。把“节点闪光”设为零，可以直接看到连线本身贡献了哪些结构。

### 4. 用四张平面制造穿行感

四层网络各自相差四分之一周期。`z` 从零增长到一时，采样尺度由 `15` 降到 `1`；采样尺度变小，屏幕上的格子便变大，看起来像在接近观察者。

```ts
const layer = float(i).div(4);
const z = fract(t.add(layer));
const size = mix(15, 1, z);
const fade = smoothstep(0, 0.6, z).mul(float(1).sub(smoothstep(0.8, 1, z)));
light.addAssign(network(st.mul(size).sub(mouse.mul(z)), layer, time, width, sparkle).mul(fade));
```

每层在周期两端淡出，因此 `fract` 回绕时不会突然切换成另一张清晰网格。拖动产生的坐标偏移也乘以 `z`，近层移动更多、远层移动更少，形成视差。它是二维分层近似，没有真实三维遮挡或透视投影。

### 5. 用缓慢变色与暗角收束画面

三个不同速度的正弦、余弦信号构成基色，乘在线条与闪光亮度上。背景辉光沿竖直方向变化；最后用到画面中心的距离平方压暗边缘，让视线集中在网络内部。

原作从黑屏渐入，并在 230 秒周期末尾淡出。本站从原作时间的第 30 秒开始，去掉整场渐入渐出，保留各深度层自己的回绕淡化，让暂停、恢复默认值和日常浏览始终有可读画面。

## 可以亲手试什么

- **穿行速度**：同时影响节点摆动、层次缩放、旋转和变色；零值冻结时间，仍可拖动观察视差。
- **星网密度**：提高后同一画幅容纳更多结构，比较前后景的疏密关系。
- **连线宽度**：观察距离遮罩边界如何改变网格的轻盈感；它是格子空间中的宽度，不是固定屏幕像素宽度。
- **节点闪光**：设为零后只看连线，再逐渐恢复脉冲光点。
- **背景辉光**：独立控制原作音频频谱曾驱动的亮度渐变；这个参数不会启动音频。

桌面按住主键拖动可观察视差，悬停不改变画面。移动端沿用滑动切换案例。暂停后仍可调整参数，恢复默认值也会重置时间与视点。

## TSL 重写要点

`Fn().setLayout()` 把哈希、节点位置、连线和整层网络编译成可复用的 WGSL / GLSL 函数。参数显式传入各层函数，便于看到时间、线宽和闪光强度如何影响结果。外层 `Loop(4)` 在 GPU 上叠加四层网络，内部九个节点由静态表达式展开。

原作多处使用反向边界的 `smoothstep`。改编统一写成 `1 - smoothstep(较小边界, 较大边界, x)`，避免依赖 GLSL 的未定义行为。旋转明确写出两个分量，保持原作行向量乘矩阵的方向。没有启用原作调试用的 SIMPLE 模式。

原始颜色按显示值解释，先用 `sRGBTransferEOTF` 转到线性空间，再交给运行时编码为 sRGB；这避免 MeshBasicNodeMaterial 重复提亮。负色值在解码前截断，中心辉光增加极小距离保护。因为浮点哈希对精度敏感，两个后端的个别节点可能存在细微差异。

## 性能观察

每个像素叠加四层，每层计算九个节点位置、十二条有效线段和九次闪光遮罩，总计 36 个节点位置、48 条线段与 36 个闪光。主要成本是逐像素的三角函数和距离计算，没有纹理读取、外部音频或粒子上传。“星网密度”改变视觉频率，但不会增加循环次数。

运行时使用自适应 DPR：桌面按 60 fps、触屏按 30 fps 的目标调整内部画布分辨率。减少动态效果时先显示静态海报，隐藏页面时暂停动画。很细的远处连线仍可能发生像素闪烁；线宽和采样分辨率会影响这种现象。

2026-09-08，Ryzen 9 7950X3D / RTX 4080 SUPER、Chromium 149.0.7827.22，生产构建预热 3 秒后采样 120 个 RAF 间隔：1440 × 900、有效 DPR 1.0 和 412 × 915、有效 DPR 1.5 两种视口下，WebGPU / WebGL2 的平均间隔均为 `6.06 ms`；WebGPU p95 为 `6.20 ms`，WebGL2 p95 为 `6.10 ms`。这是浏览器帧调度间隔，不是 GPU 执行耗时；移动视口仍使用桌面 GPU，不能替代实体手机验收。

持续注入约 45 ms/帧主线程负载时，实际画布 DPR 从 `1.0` 降至 `0.8`，确认自适应降级生效。桌面与移动两后端未产生页面或控制台错误，也没有外部音源请求。隐藏暂停通过受控 `document.hidden` / `visibilitychange` 验证，不把它等同于真实后台标签页测试。

海报和短循环来自真实浏览器画布；WebM 为 1440 × 900、25 fps、约 7 秒、VP8，无音轨，结尾半秒交叉淡化接回开头。已检查海报、视频中间帧、双后端默认帧及移动参数面板；同一时间点的原始 GLSL 对照使用居中指针和恒定 `0.15` 音频强度，构图与主要辉光结构一致。更多测试记录见同目录 VALIDATION.md。
